# Interface in the user's language

## Goal

Show the kit's interface in English, Spanish, French or German: the system's language by default, or one forced by the agent's code or by `--language=<code>` on its command line.

## Context

- Every text the kit shows a person is in English today, in both layers: the Ink views and wizard, the readline chat and console renderer, `ensureClaudeAuth()`, checkpoint titles and questions, the terminal port, and the friendly action labels of `toolLabels.ts` (core).
- The kit also writes text for the model: hook deny reasons, tool descriptions, the knowledge base prompt section, the approval tool's default texts. Several are tuned to SDK behavior confirmed by hand. They stay in English.
- The model's reply language is not part of this: each agent's prompt decides it (Captain Whiskers answers in Spanish).
- Texts the agent passes in (header, welcome, prompt label, approval and intervention texts, its own tool labels) are the agent's own and aren't translated.

## Changes

- Languages `en`, `es`, `fr`, `de`. A message catalog per language in `src/core/` (plain data, no terminal), with English as the fallback for any missing key. Placeholders for counts and names, and plurals where the text needs them (`1 turn` / `2 turns`).
- Resolving the language, in order: `--language=<code>` in the process arguments, the agent's `language` option, the system's language (`Intl` locale, then `LC_ALL`/`LANG`), then `en`. An unknown code falls back to the next source with a one-line warning. A pure resolver in core; the terminal entry points pass it `process.argv` and `process.env`.
- The `language` option wherever the kit shows text: `runChatInk()`, `runChatTui()`, `createProgressView()`, `runWizard()`, `ensureClaudeAuth()`, and `createFriendlyToolLabel()` for action labels; a desktop host passes its own language the same way.
- Translate every person-facing text: status bar, spinner, turn summary, tool group summaries and result lines, approval panel and its choices, shortcuts panel, queued/copied/interrupted/unknown-command notices, wizard answers (Yes/No), auth prompts, action labels.
- `session.log` gets the console text in the resolved language too; tooling that waits for a text of the kit's (not the agent's) must take that into account.
- Width rules still apply: every translated text is measured in columns, and the ones in fixed places (footer, panel, spinner) are cut with "…" when they don't fit. Check that the longest translation fits the status bar at 80 columns.
- captain-whiskers: accepts `--language=<code>` through the kit; its own texts stay in Spanish.
- README: one line on the supported languages and how to force one.

## Acceptance

- On a Spanish system, captain-whiskers' interface (status bar, spinner, panels, shortcuts, labels) is in Spanish; with `--language=fr` it's in French, with `--language=de` in German, with `--language=en` in English.
- An agent passing `language: "de"` gets German unless the command line says otherwise; an unsupported code warns once and falls back.
- Text for the model is unchanged in every language (test).
- Tests: the resolver's precedence, a key missing in one language falling back to English, each language's catalog having every English key, and screen frames in two languages.
- `verify` passes.
